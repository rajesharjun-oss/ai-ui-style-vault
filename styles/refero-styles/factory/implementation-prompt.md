Build requirements:

- Build an original interface inspired by the reference, not a copy of Factory.
- Do not use Factory logos, brand assets, exact screenshots, exact marketing copy, or proprietary layouts.
- Preserve the monochrome dark canvas, flat terminal surface language, tight type, compact radii,
  high-contrast light-card figure, and data-only color accents.
- Use Signal Orange (`#ee6018`) for live status, build-state marks, warnings, and chart strokes.
- Use Metric Green (`#a0ca92`) for positive metrics, success trends, and chart strokes.
- Keep primary actions neutral: dark fill on dark contexts or light fill in navigation/auth contexts.
- Avoid saturated CTA fills, soft glows, heavy shadows, parallax, or decorative gradients.
- Implement responsive layouts, accessible semantics, visible keyboard focus states, loading states,
  empty states, validation states, and safe error states.
- For real apps, enforce authentication and authorization on the server, not only in the UI.
- Document assumptions, environment variables, and setup steps.

Suggested direction:

Create a polished developer-tool or engineering dashboard interface with a full-bleed black canvas,
a left text column, a large product dashboard frame, metric tiles, a trust strip, flat feature cards,
and a restrained conversion card near the bottom.
