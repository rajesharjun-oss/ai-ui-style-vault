# Anti-Generic AI UI Checklist

## Purpose

Use this review to detect interfaces that look like a default AI-generated template rather than a product shaped by its users, content, and domain.

A single pattern is not automatically wrong. Risk appears when multiple clichés are used without a documented product reason.

## Product Specificity

- [ ] The page is built around a real user task or decision.
- [ ] Headings use product and industry language.
- [ ] The primary action is specific.
- [ ] The design could not be relabeled for an unrelated SaaS product without major changes.
- [ ] Real workflows, states, and data shapes influenced composition.

## Content Restraint

- [ ] The first viewport is not dominated by paragraphs.
- [ ] Hero support is one concise paragraph.
- [ ] Major benefits are not repeated across several sections.
- [ ] Feature cards do not contain essay-length copy.
- [ ] Detailed content is moved to dedicated pages or progressive disclosure.
- [ ] Generic AI marketing phrases have been replaced with concrete outcomes.
- [ ] Application screens use task language instead of promotional language.

## Layout Originality

- [ ] The page does not repeat the same three-card grid in every section.
- [ ] Not every text block is inside a card.
- [ ] Section rhythm varies according to content purpose.
- [ ] The product or service is visible early.
- [ ] Hierarchy is created by composition, type, and spacing—not only background colors.
- [ ] Mobile composition was designed, not merely stacked.

## Visual Discipline

- [ ] A gradient is used only when it belongs to the selected visual direction.
- [ ] Backdrop blur/glass is limited and purposeful.
- [ ] Radius hierarchy exists; every surface is not equally rounded.
- [ ] Shadows indicate elevation rather than decorate every object.
- [ ] Pill shapes are reserved for appropriate controls and tags.
- [ ] Decorative blobs, sparkles, stars, and floating badges communicate something or are removed.
- [ ] Icons are consistent and meaningful.
- [ ] Color has semantic roles and sufficient contrast.

## Typography

- [ ] Type scale is deliberate and not dominated by an oversized hero.
- [ ] Long headings wrap cleanly.
- [ ] Body line length is readable.
- [ ] Heading and body relationships match the selected theme.
- [ ] Typography works with realistic content and 200% zoom.

## Components and States

- [ ] Core components share consistent behavior.
- [ ] Loading, empty, error, success, disabled, and permission states exist where relevant.
- [ ] Tables and forms are designed for actual data and validation.
- [ ] Destructive actions include proportionate confirmation and recovery.
- [ ] Focus-visible states are present.

## Motion

- [ ] One primary motion model is used.
- [ ] Each animation has a communication purpose.
- [ ] Motion does not delay reading or task completion.
- [ ] Several animation libraries are not mixed without reason.
- [ ] Reduced-motion behavior exists.
- [ ] Mobile performance is acceptable.
- [ ] Loops and autoplay can stop or simplify.

## Authenticity Review

Ask:

1. What in this interface could only have come from understanding this product?
2. What did we intentionally remove?
3. What information became visual or interactive instead of another paragraph?
4. What happens when data is absent, invalid, slow, or restricted?
5. How does the design change on mobile beyond stacking?
6. Which visual and motion choices are documented in the recipe?
7. Is the result an original system rather than a brand imitation?

## Reject Conditions

Reject and revise when three or more of the following are prominent:

- Purple/blue gradient identity without a product reason.
- Giant headline plus several paragraphs.
- Glassmorphism across most surfaces.
- Repeated rounded card grids.
- Generic icon + title + paragraph features.
- Vague “transform/empower/unlock” copy.
- Decorative motion on most elements.
- Missing operational states.
- Desktop-only composition.
- Product hidden below long marketing content.
- Exact resemblance to one reference brand.
